# ADR 0001: Workflow Studio 改进策略

## 状态

已接受 (Accepted) - 2026-09-13

## 背景

Workflow Studio 当前存在严重的可用性问题：

1. **伪画布设计**：795行单体组件，垂直列表而非真正的图形编辑器
2. **功能缺失**：无撤销/重做、无模板复用、配置体验差
3. **心智模型不匹配**：用户期望图形化流程设计，实际得到表单填写

根据用户研究和代码分析：
- 只有2个工作流被实际使用（device_upgrade、device.health_check）
- 大部分场景是简单的命令序列执行
- Loop、Condition 等复杂节点有完整实现但几乎无实际使用

## 决策

采用**分层改进策略**，分3个阶段推进：

### 阶段1：后端增强 + 快速体验改进（2周）

**目标**：在最短时间内解决最痛的问题

**实施内容**：
1. 后端统一验证 API（1天）
2. 集成 Vue Flow 替换画布（5天）
3. 实现撤销/重做（3天）
4. 批量任务聚合显示（3天）

**不改动**：
- 保持现有组件结构（暂不拆分）
- 保持现有状态管理方式
- 保持现有数据模型

### 阶段2：组件架构重构（2周）

**目标**：降低维护成本，提升可测试性

**实施内容**：
1. 建立 Pinia store（2天）
2. 组件拆分（5天）
   - WorkflowCanvas.vue
   - NodePropertyPanel.vue
   - ConditionBuilder.vue
   - RunPreviewDialog.vue
3. TypeScript 类型完善（3天）
4. 性能优化（虚拟滚动、防抖）（2天）

### 阶段3：功能增强（2-4周）

**目标**：提升高级用户生产力

**实施内容**：
1. 智能变量引用（自动补全）
2. 改进的条件构建器
3. 模板库（3-5个内置模板）
4. 快捷键系统
5. 搜索和过滤

## 为什么选择分层改进而非重写？

### 考虑的替代方案

**方案A：渐进式重构**
- 优点：风险最小，用户无感知
- 缺点：改善速度慢，用户需要等待6周才能看到明显改进

**方案B：并行开发新版本**
- 优点：架构清晰，技术债务清零
- 缺点：投入大（8-10周），数据迁移复杂，风险高

**方案C：分层改进**（选中）
- 优点：
  - **快速见效**：2周内用户就能感受到核心改善
  - **风险可控**：Vue Flow 只替换画布组件，其他逻辑不变
  - **并行工作**：后端和前端可同时推进
  - **渐进投入**：可以在第一阶段后评估效果决定是否继续
- 缺点：
  - 仍需要3个阶段共6-8周完成全部改进
  - 第一阶段后会有临时的"混合架构"

### 关键权衡

1. **用户价值优先**：先解决"无法高效设计流程"的痛点，再解决"代码难维护"的技术债
2. **可逆性**：Vue Flow 集成是孤立的，如果效果不好可以回退，成本可控
3. **学习曲线**：团队可以在第一阶段熟悉 Vue Flow，为后续重构积累经验

## 影响

### 用户体验变化

**立即改善**（阶段1完成后）：
- ✅ 真正的图形化编辑（拖拽节点、鼠标连线）
- ✅ 操作可撤销（Ctrl+Z）
- ✅ 批量任务聚合展示

**逐步改善**（阶段2-3）：
- 响应速度提升（<100ms）
- 智能提示和自动补全
- 模板快速创建流程

### 开发体验变化

**代码结构**：
- 主组件从 795行 → 预期 <300行
- 清晰的组件边界和职责划分
- 完善的 TypeScript 类型

**维护成本**：
- 新功能开发更快（独立组件）
- Bug 定位更容易（职责清晰）
- 测试覆盖率提升（40% → 80%）

### 风险与缓解

**风险1：Vue Flow 集成失败**
- 缓解：第1周进行 POC 验证，确认可行后再全面集成
- 回退：保留旧版画布组件作为降级方案

**风险2：性能回退**
- 缓解：每个阶段后进行性能测试，确保指标达标
- 监控：建立性能基线，持续监控

**风险3：用户抵触新界面**
- 缓解：提供"经典模式"切换（保留旧版本1个周期）
- 反馈：Beta 测试收集用户意见后再全量发布

## 验收标准

### 阶段1完成标准

- [ ] Vue Flow 集成完成，支持拖拽布局
- [ ] 撤销/重做功能可用（至少支持10步历史）
- [ ] 批量任务在任务列表中聚合显示
- [ ] 所有现有测试通过
- [ ] 性能不劣于当前版本
- [ ] 现有 workflows 可无损迁移

### 最终验收标准

- [ ] 用户体验指标达标：
  - 创建10步流程时间：15分钟 → 5分钟
  - 新用户学习时间：2小时 → 30分钟
- [ ] 技术指标达标：
  - 主组件行数：795 → <300
  - 首次渲染时间：<100ms
  - 测试覆盖率：>80%
- [ ] 用户满意度评分：>4/5

## 后续计划

完成3个阶段后，根据效果评估是否继续投入：

**如果效果显著**：
- 继续开发阶段4：调试模式（单步执行、断点）
- 继续开发阶段5：协作功能（分享、评论）

**如果效果一般**：
- 暂停大规模改进
- 转向功能增强（更多内置 workflows）
- 或重新评估产品定位
