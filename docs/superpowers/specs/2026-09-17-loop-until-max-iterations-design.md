# Loop Until 最大次数语义修复设计

## 问题

Workflow Studio 的 `loop.until` 节点可能在界面显示“达到最大次数”时仍保存条件 `True`。执行器会在第一轮后判断该条件成立，因此配置的 `max_iterations` 没有机会生效。

## 根因

停止方式由前端根据 `condition` 反向推断。无法识别的条件会显示为“达到最大次数”，但不会同步改写底层条件。当前默认条件为 `True`，于是显示语义与保存、执行语义不一致。

## 修复

- 新建 `loop.until` 节点时将默认条件设为 `False`。
- “达到最大次数”模式继续明确写入 `False`，使每轮条件检查都不提前终止。
- 不修改后端循环协议；后端仍以 `condition` 成立或达到 `max_iterations` 二者之一作为终止条件。
- 不调整其他停止方式或无关的 Workflow Studio 功能。

## 验证

- 添加执行级回归测试：条件恒为假且最大次数为 20 时，子动作执行 20 次，结果报告 20 次且 `matched` 为假。
- 添加前端配置回归测试，确保默认条件和“达到最大次数”模式使用恒假条件。
- 运行相关 Python 测试、桌面端类型检查和生产构建。

## 风险

改动仅收敛“达到最大次数”的既有语义。已有明确表达式、成功、失败或输出匹配条件不受影响。
