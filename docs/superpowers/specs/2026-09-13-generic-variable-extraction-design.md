# 通用变量提取设计

## 背景

流程需要把终端命令输出中的内容保存为变量，例如从设备输出中提取 `flash:/cc`。当前流程已经支持 `variable.set` 和 `${node.field}` 引用，但缺少通用的文本提取能力。

## 目标

- 复用现有“设置变量”动作，不新增厂商、文件类型或命令专用动作。
- 支持把固定值、前置节点字段或前置节点文本中的匹配结果保存为变量。
- 默认配置保持简单，常用流程只需选择来源、填写变量名；只有需要提取时才填写匹配规则。
- 提取逻辑与设备厂商、终端命令无关。

## 用户配置

`variable.set` 保留现有字段，并增加可选提取配置：

- `name`：变量名，必填。
- `value`：固定值或完整字段引用，例如 `${command_1.output}`。
- `extract`：可选对象。
  - `pattern`：正则表达式。
  - `group`：捕获组编号，默认 `0`，表示完整匹配。
  - `mode`：`match` 保存匹配文本，`line` 保存匹配所在整行。

三种使用方式：

1. 不填写 `extract`：直接保存 `value`。
2. `value` 引用前置节点输出并填写 `extract.pattern`：保存第一个匹配结果。
3. 配置 `extract.group`：保存指定捕获组，用于从一行文本中提取路径、地址或版本号。

示例：

```json
{
  "name": "cc_path",
  "value": "${command_1.output}",
  "extract": {
    "pattern": "(?i)(?:flash|cfcard):/\\S*cc\\S*",
    "group": 0,
    "mode": "match"
  }
}
```

## 运行时数据

执行结果继续保留原有的 `name` 和 `value`，并增加：

```json
{
  "name": "cc_path",
  "value": "flash:/cc",
  "matched": true,
  "source": "...原始文本..."
}
```

未匹配时不让流程静默使用错误值：

```json
{
  "name": "cc_path",
  "value": "",
  "matched": false,
  "source": "...原始文本..."
}
```

流程可以用 `${set_cc.matched}` 连接条件节点，也可以引用 `${cc_path}` 使用提取值。默认策略是“第一个匹配”；不引入多结果数组，避免界面和执行语义变复杂。

## 实现边界

- 在通用工作流执行层增加可复用的字符串提取函数，使用 Python 标准库正则表达式。
- `variable.set` 负责解析引用、执行可选提取并输出结果；不感知华为 VRP 或其他厂商。
- 前端只在选中“设置变量”时显示一个简洁的“提取匹配”折叠配置；关闭时不增加额外字段。
- 正则无效时节点失败并返回明确错误；无匹配是正常结果，由 `matched=false` 表达。
- 继续沿用现有变量名校验和 `${node.field}` 的前置节点引用校验。

## 验证

- 直接保存字符串、数字和布尔值。
- 保存前置节点完整输出。
- 正则完整匹配和捕获组提取。
- 无匹配、无效正则和空源文本。
- 条件节点根据 `matched` 正确选择分支。
- 前端类型检查、构建和现有工作流测试不回归。

## 非目标

- 不新增“检查文件”“提取版本”“匹配华为”等专用动作。
- 不支持任意脚本或用户自定义 Python/JavaScript 表达式。
- 不在本次变更中修改设备命令执行、终端分页或厂商适配逻辑。
