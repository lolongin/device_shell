# Device TUI PRD

## 1. 文档说明

本文档用于描述 `device_tui` 项目的产品需求，分为两部分：

- 当前实现：当前代码已经具备的能力
- 目标需求：建议后续版本补齐和优化的方向

本文档主要面向产品、开发和测试协作场景，用于统一理解、排定优先级和制定验收标准。

## 2. 产品定位

`Device TUI` 是一个基于 Textual 的终端设备管理看板，面向运维、测试和实验室设备使用人员，提供设备浏览、筛选、占用管理和快捷连接能力。

产品目标是让用户在终端内完成以下核心动作：

- 快速定位目标设备
- 查看设备连接与资产信息
- 占用或释放设备
- 发起 SSH 或 Telnet 连接

## 3. 目标用户

### 3.1 运维人员

关注点：

- 快速查看设备状态
- 判断设备是否被占用
- 直接连接设备处理问题

### 3.2 测试人员

关注点：

- 快速筛选符合条件的测试设备
- 占用空闲设备避免冲突
- 查看版本、CPU、站点等信息

### 3.3 值班人员

关注点：

- 查看本人当前占用设备
- 快速在多台设备之间切换
- 处理临时任务和释放资源

## 4. 当前版本范围

当前版本已实现：

- 设备列表展示
- 组合筛选
- 统计条
- 我的占用列表
- 设备详情展示
- 密码显隐
- 设备占用和释放
- SSH/Telnet 连接
- 键盘和鼠标交互
- 窗口尺寸自适应

当前版本未实现：

- 数据持久化
- 后端服务
- 多用户实时同步
- 权限控制
- 设备在线状态探测
- 外部配置或 API 数据源

## 5. 版本目标建议

建议将后续演进拆为三个阶段：

### 5.1 V1.0 当前版

目标：

- 完成终端看板基础闭环
- 支持样例数据浏览和本地交互

### 5.2 V1.1 建议版

目标：

- 完善文档和验收标准
- 优化搜索与筛选体验
- 补充异常处理和最小测试集

### 5.3 V2.0 业务可用版

目标：

- 接入外部数据源
- 引入持久化与权限控制
- 支持多用户并发占用

## 6. 核心用户场景

### 场景 1：测试人员快速寻找空闲设备

用户希望：

- 输入领域关键字
- 输入 CPU 关键字
- 选择“空闲”状态
- 快速定位符合条件的设备并占用

成功标准：

- 3 步以内完成筛选
- 结果实时刷新
- 占用成功后主列表、我的占用、统计条同步变化

### 场景 2：运维人员查看设备详情并发起连接

用户希望：

- 从列表中选择目标设备
- 查看连接地址、账号、版本、站点等信息
- 直接发起 SSH 或 Telnet 连接

成功标准：

- 详情切换无明显延迟
- 连接命令正确拼接
- 命令缺失时有明确报错

### 场景 3：值班人员管理本人设备

用户希望：

- 在“我的占用”列表查看自己正在使用的设备
- 释放不再使用的设备
- 在两个列表和详情区之间快速切换

成功标准：

- “我的占用”列表可正确联动详情
- 释放操作后列表和统计立即更新

### 7.3 左侧我的占用区

包含：

## 8. 功能需求清单

以下需求分为：

- `P0`：必须具备，影响核心闭环
- `P1`：重要优化，影响效率和体验
- `P2`：后续增强

### 8.1 启动与初始化 `P0`

需求说明：

- 应用启动后加载样例设备数据
- 默认选中第一台设备
- 默认显示全部设备
- 默认密码隐藏
- 默认焦点落在主设备列表
- 启动时立即渲染详情、统计、筛选建议和列表

### 8.2 主设备列表 `P0`

需求说明：

- 每一行对应一台设备
- 列表显示当前筛选结果
- 当前选中设备高亮
- 窗口变化时自动重绘

宽屏列定义：

- `No`
- `Device`
- `Domain`
- `CPU`
- `Status`
- `Owner`

窄屏列定义：

- `No`
- `Device`
- `Domain`
- `CPU`
- `Status`

交互要求：

- 方向键移动高亮
- 选中或高亮变化时同步更新详情区

### 8.3 我的占用列表 `P0`

需求说明：

- 显示当前筛选结果中，占用人为当前用户的设备
- 与主列表共享选中状态
- 选中或高亮时同步更新详情区

紧凑列定义：

- `No`
- `Device`
- `Domain`

产品建议：

- 当前行为容易让用户误解为“我的全部占用”
- 建议在后续版本考虑改为展示全部本人占用设备，或在界面中明确说明其受筛选条件影响

### 8.4 统计条 `P0`

需求说明：

- 统计对象为“当前筛选结果”
- 实时显示以下数量：
  - 总数
  - 已被占用
  - 空闲
  - 流水线占用
  - 其他

### 8.5 关键字搜索 `P0`

需求说明：

- 支持大小写不敏感
- 使用包含匹配
- 输入变化后实时刷新

当前搜索字段：

- 设备 ID
- 设备名称
- SSH IP
- Telnet IP
- 设备型号 `model`

优化建议 `P1`：

- 扩展支持 `domain`、`vendor`、`site`、`notes`
- 在界面中明确标注当前搜索范围

### 8.6 领域筛选 `P0`

需求说明：

- 支持大小写不敏感
- 使用包含匹配
- 输入变化后实时刷新
- 支持自动建议

建议词来源：

- 优先当前筛选结果中的领域值
- 为空时回退为全部设备中的领域值

### 8.7 CPU 筛选 `P0`

需求说明：

- 支持大小写不敏感
- 使用包含匹配
- 输入变化后实时刷新
- 支持自动建议

建议词来源：

- 优先当前筛选结果中的 CPU 值
- 为空时回退为全部设备中的 CPU 值

### 8.8 状态筛选 `P0`

状态项：

- 全部状态
- 已被占用
- 空闲
- 流水线占用
- 其他

需求说明：

- 同时仅允许一个状态被激活
- 点击后实时刷新
- 当前激活项高亮

### 8.9 组合筛选 `P0`

当前生效条件：

- 关键字搜索
- 领域筛选
- CPU 筛选
- 状态筛选

组合规则：

- 四类条件按“与”关系生效

优化建议 `P1`：

- 增加“一键清空筛选”
- 增加筛选条件可见回显

### 8.10 空结果提示 `P0`

当无匹配设备时，应：

- 清空主列表
- 清空我的占用列表
- 清空当前选中设备 ID
- 在详情区显示提示信息

### 8.11 设备详情 `P0`

详情区需显示：

- 设备名称
- 设备 ID
- 领域
- 设备类型
- SSH IP
- Telnet IP
- 用户名
- 密码或掩码密码
- 状态
- 占用人
- CPU
- 厂商
- 型号
- 版本
- 站点
- 机架
- 备注

展示规则：

- 无占用时显示 `Unassigned`
- 密码默认脱敏
- 当前用户为占用人时高亮显示
- 状态按颜色区分

### 8.12 密码显隐 `P0`

需求说明：

- 按 `p` 切换密码显示状态
- 切换后刷新详情区
- 显示成功通知

安全建议 `P1`：

- 默认保留脱敏
- 后续可增加权限校验或二次确认
- 后续可切换为环境变量或密钥管理方式

### 8.13 设备占用与释放 `P0`

触发方式：

- `o`
- 主列表双击
- 我的占用列表双击

状态流转规则：

- 当 `owner == CURRENT_USER` 且 `status == 已被占用` 时，可释放
- 当 `owner is None` 且 `status == 空闲` 时，可占用
- 其他状态不允许变更，仅提示当前状态

变更后需同步刷新：

- 主列表
- 我的占用列表
- 统计条
- 详情区

建议补充的状态机说明 `P1`：

- 谁能释放谁占用的设备
- 流水线占用是否允许人工接管
- “其他”状态的业务含义

### 8.14 SSH 连接 `P0`

模式：

- `s`：当前终端连接
- `S`：外部窗口连接

需求说明：

- 检查本机是否有 `ssh` 命令
- 命令不存在时提示错误
- 命令存在时执行 `ssh <username>@<ssh_ip>`
- 关闭后显示提示

### 8.15 Telnet 连接 `P0`

模式：

- `t`：当前终端连接
- `T`：外部窗口连接

需求说明：

- 检查本机是否有 `telnet` 命令
- 命令不存在时提示错误
- 命令存在时执行 `telnet <telnet_ip>`
- 关闭后显示提示

### 8.16 焦点切换与效率操作 `P1`

需求说明：

- `Tab` 切换下一个焦点
- `Shift+Tab` 切换上一个焦点
- `/` 直接聚焦主搜索框
- 自动建议输入框支持 `Tab` 接受建议

### 8.17 鼠标交互 `P1`

需求说明：

- 左键双击设备项时先选中再执行占用/释放
- 单击不触发占用动作

### 8.18 窗口尺寸自适应 `P1`

需求说明：

- 重新计算列表列宽
- 重绘表头和列表
- 保持详情展示同步更新

## 10. 数据来源规划建议

### 10.1 当前实现

- 数据来源为内置样例函数 `sample_devices()`
- 数据仅存在内存中

### 10.2 建议演进

第一阶段：

- 保持样例数据
- 补充更多状态和异常场景样例

第二阶段：

- 支持本地配置文件加载，如 `json/yaml/csv`

第三阶段：

- 支持从远程 API 拉取数据
- 支持占用状态回写

## 11. 异常与边界场景

建议明确纳入需求和验收的场景包括：

- 搜索无结果
- SSH 命令不存在
- Telnet 命令不存在
- 外部终端拉起失败
- 设备字段缺失或为空
- 窗口宽度过小导致列压缩
- 尝试占用非空闲设备
- 尝试释放非本人占用设备
- 数据源加载失败

## 12. 非功能性要求

### 12.1 运行环境

- Python `3.10+`
- `textual>=0.61,<0.70`
- 命令行终端环境

### 12.2 平台适配

当前实现偏向 Windows：

- 优先使用 `wt`
- 回退使用 `powershell`

建议 `P1`：

- 后续补充跨平台终端启动策略

### 12.3 性能要求

- 当前数据量下，筛选操作应即时响应
- 不要求异步加载

### 12.4 安全要求

当前现状：

- 样例数据中包含明文账号和密码
- 密码可在界面中显示

建议目标：

- 默认脱敏展示
- 敏感信息来源可切换到环境变量或安全存储
- 明确禁止提交真实生产凭据

## 13. 已知限制

- 数据不持久化，重启后状态丢失
- 无并发占用控制
- 无后端同步机制
- 搜索字段覆盖范围有限
- 我的占用列表受当前筛选条件影响
- 占用逻辑仅支持“空闲”和“已被占用（本人）”之间切换
- 连接能力依赖本机命令安装情况

## 14. 验收标准

### 14.1 功能验收

1. 启动应用后默认选中第一台设备。
2. 主列表、我的占用、详情区均正常渲染。
3. 关键字、领域、CPU、状态筛选均可实时生效。
4. 统计条随筛选结果同步变化。
5. 选中设备变化时详情区同步更新。
6. 密码显隐切换正确，通知正确。
7. 空闲设备可被当前用户占用。
8. 当前用户已占用设备可被释放。
9. 非空闲设备或非本人设备不会被错误释放或占用。
10. SSH/Telnet 命令存在时能正确调用。
11. SSH/Telnet 命令不存在时会显示错误提示。
12. 窗口尺寸变化后列表显示正常。

### 14.2 体验验收

1. 主要操作可仅通过键盘完成。
2. 筛选和选择反馈应即时。
3. 错误提示要明确，不让用户猜测原因。

## 15. 测试建议

在未建立自动化测试前，建议至少保留以下人工回归清单：

1. 搜索字段匹配验证
2. 领域/CPU 自动建议验证
3. 状态筛选切换验证
4. 占用与释放状态流转验证
5. 我的占用联动验证
6. 密码显隐验证
7. SSH/Telnet 命令拼接验证
8. 空结果提示验证
9. 窗口缩放验证

建议后续补充 `pytest` 测试时优先覆盖：

- 筛选函数逻辑
- 状态流转逻辑
- 搜索索引逻辑
- 密码掩码逻辑

## 16. 后续建议

如果准备继续做这个项目，我建议优先按下面顺序推进：

1. 先把“当前实现”和“目标版本”彻底区分，避免文档既像说明书又像规划稿。
2. 再补一个轻量技术设计，明确数据源、状态管理和安全方案。
3. 然后优先做 `P1` 中最影响体验的两项：搜索范围扩展、清空筛选。
4. 最后再推进持久化和 API 化，不然前面的交互规则还可能继续变化。
