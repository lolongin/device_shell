# Workflow Studio 改进项目 - 执行摘要

## 🎯 项目目标

将 Workflow Studio 从"勉强能用"提升到"好用且强大"，解决核心可用性问题，提升用户生产力。

---

## 📊 现状分析

### 核心问题

经过深度分析，我们识别出三大类问题：

#### 1. **可用性危机**（影响最大）
- **伪画布设计**：垂直列表而非真正的图形编辑器
- **手动连接管理**：通过下拉菜单选择上下游，繁琐易错
- **单体组件**：795行代码，难以维护和扩展

#### 2. **功能缺失**（明显影响体验）
- ❌ 撤销/重做
- ❌ 模板库和复用机制
- ❌ 批量任务聚合显示
- ❌ 智能提示和自动补全
- ❌ 调试能力

#### 3. **心智模型不匹配**（深层问题）
- 用户期望：图形化流程设计工具
- 实际提供：列表 + 表单组合
- 结果：学习曲线陡峭，效率低下

### 使用数据洞察

- 只有 **2个工作流**被实际使用（device_upgrade、device.health_check）
- 大部分场景是**简单命令序列**执行
- Loop、Condition 等复杂节点**几乎无实际使用**
- 说明：**过度设计** vs **实际需求**存在偏差

---

## 💡 解决方案

### 设计原则

1. **用户价值优先**：先解决最痛的问题
2. **快速见效**：2周内用户感受到改善
3. **渐进式改进**：降低风险，保持系统稳定
4. **并行工作**：前后端同时推进

### 核心决策

#### 决策1：分层改进策略（而非重写）

**原因**：
- ✅ 风险可控
- ✅ 快速见效（2周 vs 10周）
- ✅ 可以中途评估调整
- ✅ 保持系统稳定性

**权衡**：
- ⚠️ 会经历"混合架构"阶段
- ⚠️ 需要3个阶段才能完全改进

**详见**：[ADR 0001](./adr/0001-workflow-studio-improvement-strategy.md)

#### 决策2：Batch Task 作为一等公民

**原因**：
- ✅ 符合业务语义（用户关心"这次升级"而非"20个独立升级"）
- ✅ 支持批量控制（暂停/取消/重试）
- ✅ 简化报告生成

**影响**：
- 任务列表从"100条记录"变为"1个批次 + 展开查看详情"
- 新增 batch_tasks 表和 API

**详见**：[ADR 0002](./adr/0002-batch-task-as-first-class-entity.md)

## 🗺️ 实施路线图

### 阶段1：后端增强 + 快速体验改进（2周）⭐ **当前重点**

**交付物**：
1. ✅ **真正的图形编辑器**（Vue Flow）
   - 拖拽节点布局
   - 鼠标连线
   - 自动布局算法

2. ✅ **撤销/重做**
   - Ctrl+Z / Ctrl+Shift+Z
   - 最多50步历史

3. ✅ **批量任务聚合**
   - 任务列表显示批次卡片
   - 聚合状态（成功/失败/进行中）
   - 批量控制（暂停/重试/取消）

4. ✅ **增强的验证信息**
   - 修复建议（fix_suggestion）
   - 文档链接（doc_link）
   - 影响范围（affected_nodes）

**成功标准**：
- 用户可以用鼠标拖拽设计流程（而非填表单）
- 操作可撤销，降低试错成本
- 批量任务在列表中清晰呈现

**详细计划**：[stage1-detailed-plan.md](./implementation/stage1-detailed-plan.md)

---

### 阶段2：组件架构重构（2周）

**交付物**：
- Pinia store 状态管理
- 组件拆分（WorkflowCanvas、NodePropertyPanel、ConditionBuilder 等）
- TypeScript 类型完善
- 性能优化（虚拟滚动、防抖、缓存）

**目标**：主组件从 795行 → <300行

---

### 阶段3：功能增强（2-4周）

**交付物**：
- 智能变量引用（输入 `${` 自动补全）
- 改进的条件构建器（可视化规则编辑）
- 模板库（3-5个内置模板）
- 快捷键系统（复制/粘贴/删除）
- 搜索和过滤

**目标**：高级用户生产力提升 50%

## 🏗️ 技术架构

### 前端技术栈

- **Vue 3** + TypeScript
- **Vue Flow** - 图形编辑器核心
- **Pinia** - 状态管理
- **ELK.js** - 自动布局算法

### 后端技术栈

- **Python 3.11+**
- **FastAPI** - HTTP API
- **SQLite** - 持久化
- **Dataclasses** - 领域模型

### 新增依赖

```bash
# 前端
npm install @vue-flow/core @vue-flow/background @vue-flow/controls @vue-flow/minimap elkjs

# 后端（无新增，使用现有依赖）
```
