# 共享目录路径输入易用性设计

## 目标

让 Workflow 的文件上传/下载路径支持用户自然输入的 Windows 路径，同时保证最终路径仍被限制在配置的文件传输共享目录内。

## 行为

- 接受 `file.cc`、`packages/file.cc`、`packages\\file.cc`、`.\\packages\\file.cc` 等写法，并规范化为统一的 POSIX 相对路径。
- 用户粘贴共享目录内的绝对路径时，后端根据共享目录自动转换为相对路径。
- 绝对路径位于共享目录外、包含 `..` 越界片段、空路径或指向目录时继续拒绝。
- Workflow Studio 的运行参数输入在提交前执行同样的规范化，并回显规范化后的值。
- 节点配置、运行参数、API/MCP 调用共用后端规范化逻辑，避免入口间行为不一致。
- 错误信息说明共享目录约束和实际解析结果，但不泄露共享目录之外的敏感信息。

## 实现边界

- 在 `managed_file_transfer` 中增加纯函数式路径规范化入口，供校验和文件解析复用。
- 在 Workflow Studio 前端对 `package_path` 等文件型输入做即时规范化；前端无法判断共享目录时只做分隔符和 `./` 前缀处理。
- 在工作流运行 API 组装 TaskPlan 前，对上传/下载参数进行后端规范化；变量引用保留到编排器运行时解析。
- 不放宽共享目录 containment 检查，不允许通过符号链接或 `..` 逃逸。

## 测试

- 单元测试覆盖 Windows 分隔符、`./`/`.\\` 前缀、共享目录内绝对路径、目录外绝对路径、`..` 越界和空值。
- Workflow API 回归测试确认规范化后的 `source_path` 传入 TaskPlan。
- 前端类型检查和生产构建必须通过。
